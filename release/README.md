# Qure — 제출용 APK

QR 피싱(quishing) 탐지 안드로이드 앱. 스캔한 주소를 **열기 전에** 보여주고 검사합니다.

| | |
|---|---|
| 파일 | `Qure-v0.1.0.apk` (23MB, 서명 완료) |
| 최소 사양 | **Android 8.0 (API 26)** 이상 |
| 검증 기기 | Galaxy S22 (Android 16 / API 36) |
| 설치 | 파일 열기 → "출처를 알 수 없는 앱" 허용 → 설치 |

Google Play를 거치지 않으므로 설치 시 "알 수 없는 앱 설치" 허용이 한 번 필요합니다.

## 시연용 계정

| 구분 | ID | PW | 플랜 |
|---|---|---|---|
| **슈퍼 계정** | `test` | `1234` | **Pro** |
| 관리자 | `admin` | `0000` | Pro |

- 회원가입 없이 바로 로그인됩니다. 앱 데이터를 지워도 유지됩니다.
- **로그인 없이도 QR 검사 기능은 전부 동작합니다.** 계정은 요금제를 기기가 아닌 계정에
  묶어두기 위한 것이고, 안전 판정을 막는 데는 쓰이지 않습니다.
- 비로그인 상태에서는 Pro 요금제를 선택할 수 없고, 블랙리스트는 10개로 제한됩니다.

> 이 계정들은 심사·시연 편의를 위해 앱에 내장한 것입니다. 소스의
> `com.qure.app.demo.DemoAccounts` 한 곳에 모여 있습니다.

## 실행 시 유의점

**1. 카메라 권한이 필요합니다.**
첫 실행 시 요청합니다. 촬영하거나 저장하지 않고, 화면에 보이는 QR만 그 자리에서 읽습니다.
권한을 거부해도 마이페이지·블랙리스트 등 나머지 화면은 그대로 쓸 수 있습니다.

**2. 목적지 확인 시 실제로 접속합니다.**
단축 주소의 최종 목적지를 알아내기 위해 **해당 주소로 직접 요청을 보냅니다**(HEAD 요청만
보내고 본문은 받지 않습니다). 따라서 상대 서버는 접속 사실과 기기 IP를 알 수 있습니다.
스캔한 내용 자체가 외부로 전송되는 일은 없습니다. 인터넷이 없으면 1차(오프라인) 검사만
수행하고, 그 사실을 화면에 명시합니다.

**3. 검사가 실패하면 "불완전"으로 표시됩니다.**
존재하지 않는 도메인이나 네트워크 오류로 목적지를 확인하지 못하면
`일부 검사 규칙이 실행되지 않아 결과가 불완전합니다`가 뜹니다.
**정상 동작입니다** — 검사 실패를 "안전"으로 표시하지 않는다는 설계 원칙이 화면에 드러난
것입니다. 아래 테스트 QR 중 가짜 도메인 카드에서 이 화면을 볼 수 있습니다.

**4. 기본 카메라 연동은 별도 설정이 필요합니다.**
삼성 카메라 등으로 찍은 QR 링크를 Qure가 먼저 검사하게 하려면, 앱 안에서
**기본 브라우저 역할**을 Qure에 부여해야 합니다(메뉴 → 기본 카메라 연동).
Android 12부터 도메인 미검증 웹 링크는 선택창 없이 기본 브라우저로 직행하기 때문에,
이 역할 없이는 가로챌 방법이 없습니다. QR 출처가 아닌 링크는 화면 없이 즉시 통과시킵니다.

**5. 세로 화면 전용입니다.**

## 테스트 방법

같은 폴더의 **`test-qr.html`을 PC 브라우저에서 열고** 앱으로 스캔하십시오.
16개 QR 각각에 기대되는 색·점수·발동 규칙이 함께 적혀 있습니다.

먼저 보실 만한 3가지:

| QR | 확인 포인트 |
|---|---|
| `https://www.kakaobank.com` | 🟢 **100점** — 진짜 은행을 사칭으로 오인하지 않음 (오프라인이면 95점) |
| `https://www.kakaobank.com@evil.example/login` | 🔴 **15점** — `@` 앞은 장식, 실제 목적지는 evil.example |
| `http://naver.com` | 🟡 **67점** — 리다이렉트를 따라가 www.naver.com 도착을 표시 |

두 번째가 이 앱의 핵심입니다. 사람 눈에는 카카오뱅크 주소로 보이지만 실제 접속지는
`evil.example`이며, QR은 목적지를 눈으로 확인할 수 없기 때문에 이 수법이 통합니다.

## 판정 방식

색은 **가장 심각한 신호 하나**로만 결정합니다. 점수·개수·합계는 색 결정에 관여하지 않습니다.
점수(0~100)는 색이 정해진 **뒤에** 그 색의 구간 안에서 계산되는 표시용 값입니다.

| | 점수 구간 |
|---|---|
| 🟢 안전 | 85 ~ 100 |
| 🟡 주의 | 40 ~ 84 |
| 🔴 위험 | 0 ~ 39 |

점수 합산이 색을 바꿀 수 있으면, `@` 위장 같은 결정적 신호 하나가 다른 신호가 없다는 이유로
노랑으로 내려가거나 가벼운 경고 여러 개가 쌓여 빨강이 됩니다. 둘 다 각 심각도가 단독으로
하는 약속을 깨기 때문에 구조적으로 막아두었습니다.
